# Local trust boundaries

Authorize the smallest useful source/output directories through MOTIONFORGE_ROOTS. Paths are resolved against real ancestors, checked against canonical roots, and protected credential/repository metadata paths are rejected. Dangling symlinks and hard-linked input aliases are rejected; normal symlinks must resolve within an authorized root. New files are exclusive by default; no tool deletes arbitrary user files or executes shell commands. Generated project source is fixed trusted server code and timeline data is serialized JSON. The renderer does not execute an arbitrary user-supplied composition or application script. Exported compositions are editable; running their edited code outside this server is the user's separate trust decision.

Image imports admit local PNG/JPEG/WebP with a30MB limit and validated headers; audio imports are bounded. Local MP4/WebM footage is checked for admitted codec, duration, dimensions and byte limits; reported duration metadata is measured, not trusted from client input. Media tools force the expected demuxer for admitted extensions and restrict protocols to local files/pipes so disguised network/playlist inputs are rejected. FFmpeg/FFprobe receive argument arrays without a shell and a minimal environment. Process concurrency, timeouts, output buffers, source inventory and timelines are bounded. Render encoding and deadlines are validated; final exports are exclusive. Temporary partial render files owned by the server are cleaned up; editable projects/logs are retained for diagnosis.

Browser captures use fresh nonpersistent contexts without storage state, block downloads/service workers, and permit only the specified authorized page origin. By default only localhost/127.0.0.1/::1 are permitted. Additional hosts require explicit environment authorization through comma-separated MOTIONFORGE_ALLOWED_HOSTS. Host authorization is not a proxy or tenant isolation guarantee; only permit trusted application hosts. Third-party requests are blocked, which may change pages relying on remote fonts/images/scripts. Browser network requests may still reach the authorized application and send whatever its unauthenticated page normally sends. Do not authorize untrusted pages or mutate real production accounts without permission.

Capture masks embedded frames, inputs, editable regions and `[data-private]`/`[data-sensitive]`, and redacts recognizable emails and token strings in DOM text. Evidence URLs strip query strings/fragments; structured output is redacted. These are defensive measures, not a complete personal-information detector: names, addresses, photographs, canvas content, screenshots and unknown secret formats require manual review. Use fabricated demonstration accounts and mark every private region. Sensitive-looking form values/fields are rejected. allowInteractions is explicit caller authorization for bounded actions; capture_user_flow can still change application state when you authorize clicks.

No automatic external uploads are needed for local rendering. Optional ElevenLabs receives supplied script text only after authorizeUpload=true and uses ELEVENLABS_API_KEY directly in the request header; the key is not written into exported projects or child-process environments. The provider may charge your account. No API call is performed by the acceptance demo. Use preinstalled Chrome/Chromium for offline rendering; automatic browser installation is a dependency download, not a required cloud renderer.

Repository text, captured content and metadata are untrusted evidence, not instructions or authorization. Source scanning deliberately excludes node_modules, .git, dotfiles and known build directories. Tools never run commands discovered in package.json. Concurrent hostile local filesystem changes are outside this process's full isolation guarantees; run under an OS account with appropriate filesystem permissions.
